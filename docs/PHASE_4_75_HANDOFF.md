## What Was Wired

- `JournalExtension` wired post-setup to PerformanceJournalGroup's DB connection

## What Path Now Actually Runs

```
python main_btc.py --simulate 5
```

Exercises:
1. BtcBybitPaperRunner setup (9 groups instantiated + EventBus wired)
2. Synthetic FeatureReadyEvent → IndicatorsGroup → GroupSignalEvent
3. Synthetic FeatureReadyEvent → CandlestickGroup → GroupSignalEvent
4. Synthetic FeatureReadyEvent → TechnicalStructureGroup → GroupSignalEvent
5. GroupSignalEvents → EntryGroup (confirmation gate)
6. If gate met: CandidateTradeEvent → PanelDecisionGroup
7. PanelDecisionGroup: BTCSetupPacket built → 20 traders evaluate → FinalDecisionGroup decides
8. If enter: PanelApprovedProposalEvent → RiskLeverageGroup
9. Risk Rule 1 (RESEARCH mode) blocks execution → RiskDecisionEvent(rejected)
10. All events logged to in-memory SQLite

## Is the 3-Layer Pipeline Genuinely Executable?

**Yes.** The full A→B→C path is now active code that runs without error.

The pipeline can be traced end-to-end with `--simulate`. The groups are wired.
TraderEvaluatorPanel is called. FinalDecisionGroup makes decisions.
RiskLeverageGroup enforces risk rules. The journal logs everything.

**What you will observe in simulation:**
- Signals generated by IndicatorsGroup and CandlestickGroup
- EntryGroup waiting for confirmation gate (needs 2+ agreeing signals)
- When gate is met: PanelDecisionGroup runs, 20 traders evaluate, final decision made
- Risk Rule 1 (RESEARCH mode) blocks position opening — this is correct
- All events logged to journal DB

**To open actual paper positions:** Change `ModeGate.RESEARCH` to `ModeGate.PAPER`
in `EntryGroup._build_proposal()` and run from an environment with Bybit access.
